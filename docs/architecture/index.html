Deployment history

Initial deployment · Direct installation as ubuntu

The official installer placed OpenClaw under /home/ubuntu/.npm-global/. Its binary directory was added to PATH. The Gateway and tools ran on the host under ubuntu, whose broad administrative privileges were an accepted laboratory limitation. Nexus used /home/ubuntu/.openclaw/workspace/.

The initial deployment verified SSH, private Dashboard access, a responding agent, and OpenAI connectivity. It also documented disabling the 30-minute heartbeat and the daily memory dreaming job. Those settings describe the original deployment.

Experiment 003 · Ansible installation under nexus

The lab ran the local Ansible playbook from recorded revision 238f100. SSH administration remained with ubuntu. Ansible created nexus with its own home, scoped sudo grants, and no Docker group membership. The host ran rootful Docker. The Gateway ran as a systemd user service under Nexus.

The experiment resolved two startup failures involving unsafe permissions on /home/nexus/.config and an earlier onboarding process holding Gateway state. Loopback listening and the deep connectivity check were verified after recovery. The operator opened the Dashboard through SSH and demonstrated conversational bootstrap. Some workspace actions were agent-reported.

November 9 · Telegram channel and Dashboard observation

The Telegram bot used an allowlisted maintainer account and skipped chat-based administrative privileges. Nexus received and answered messages in Spanish. The Dashboard displayed incoming messages, replies, and agent operations while it was open. Nexus reported using GPT-5.6 Sol with medium reasoning. Effective model selection, internal session IDs, and channel operation with the SSH tunnel closed remain to be checked.

Runtime and data

Host and storage

Ubuntu 24.04 LTS on a t3.medium (2 vCPU, 4 GiB), with a 30 GiB gp3 root volume and 2 GiB swap. The documented design uses encrypted EBS, IMDSv2, and no instance IAM role. Workspace and runtime state are stored on EC2.

Network boundary

The security group allows SSH from the maintainer’s current public IPv4. The Gateway binds to loopback on port 18789. The Dashboard uses an SSH tunnel. Public addresses can change after stop/start.

Tools and permissions

Routine workspace work is guided by agent instructions. Linux identities, sudo, filesystem permissions, and effective tool policies determine technical access. Container installation and active container execution are separate checks.

Agent workspace

Nexus uses IDENTITY.md for presentation, SOUL.md for behavior, USER.md for preferences, and AGENTS.md for operating instructions. Long-term memory may use MEMORY.md and memory/. The Experiment 003 workspace is under /home/nexus/.openclaw/.

Models and memory

OpenAI inference was exercised. Initial API usage showed embedding calls. Experiment 003 skipped embeddings during onboarding. Controlled retrieval comparisons and local embeddings are pending. Gemini is planned.

Background activity

The initial experiment disabled heartbeat and dreaming. The architecture records those actions for the initial installation. Effective scheduling on later installs requires its own check. Compute, storage, inference, and embeddings contribute separate costs.

Research directions

Tool isolation and service hardening

Evaluate a sandbox backend, including rootless Docker as an option. Validate restricted commands, workspace mounts, filesystem boundaries, network access, and approvals independently. Inspect browser execution, service configuration, and backup and recovery. Production systems and credentials stay outside the lab.

Hybrid memory and model selection

The proposed flow keeps conversational reasoning on a cloud API and tests a local embedding model feeding a local memory index. Compare retrieval quality, privacy, resource usage, operational complexity, and costs. Evaluate model latency, reliability, and tool use separately.

Specialized agents and potential applications

Later experiments can test delegated agents, scheduled work, and human review. The original architecture proposes affiliate research and WordPress drafting as a future application after lab validation.
