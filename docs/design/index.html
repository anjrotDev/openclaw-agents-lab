HTML design conventions

Reusable patterns for guides, experiments, and architecture pages.

Palette · Typography · Navigation · Components · Interaction · Review

Palette

Experiment 004 defines the base palette. Use the white canvas for reading, pale teal for orientation and grouped content, and deep blue for code or a featured action.

Canvas--paper · #FFFFFF
Panel--panel · #EDF5F6
Primary text--ink · #182D39
Secondary text--muted · #466070
Links and focus--accent · #095D65
Border--line · #CCD9DE
Dark surface--deep · #142B36
Text on dark--on-deep · #EFF8FA

Additional colors are useful for meaningful data categories. Pair each color with a label or shape. Use the accent for links and focus, and keep links underlined in body copy. Check WCAG AA contrast for new foreground and background combinations.

Typography

Use system-ui, sans-serif for headings and body text, and ui-monospace, monospace for commands, paths, and output. Start with a 1 rem body size and 1.65 line height. Scale headings with clamp(). Experiment 004 uses clamp(2rem, 5vw, 3.7rem) for its page title. Keep reading passages near 65–75 characters per line where the layout permits.

Navigation

  • Use one descriptive page title, a visible link back to the lab homepage, and stable section IDs. Add a table of contents when the page spans several sections.
  • Use repository-relative links and explicit filenames such as ../../index.html. The lab is opened directly from disk as well as through uploaded previews.
  • Let a sidebar index become a normal inline block on narrow screens. Group source material and related experiments near the relevant section or in a sources section.

Components

Reading header and cards
Use a pale panel for page orientation and a dark surface for a single featured route. Cards work for parallel topics and component descriptions.
Evidence table
Use scoped headers, text labels for implemented, verified, and pending work, and a keyboard-focusable horizontal scroll region when needed.
Commands and output
Use <pre><code> with horizontal scrolling. Identify the execution context and keep commands visually distinct from expected output.
Flow diagrams
Use labeled nodes and directional relationships. Add a caption or nearby text describing the flow. Stack nodes vertically when horizontal space runs out.
Example disclosure · Supporting evidence

Use native disclosures for full records, optional detail, and troubleshooting branches. Keep required steps and important status visible. If an anchor points into a closed disclosure, open that disclosure when navigating to the anchor.

Interaction and offline use

Prefer native HTML and CSS for navigation, disclosures, tables, and simple diagrams. Use JavaScript when it makes a task easier, such as filtering learning routes or opening an appendix from a section link. Keep core content readable with scripts disabled. Make controls keyboard operable and give dynamic result counts a status region.

The current pages use native HTML, CSS, and plain JavaScript. They load zero third-party libraries. If a future document benefits from a diagram, chart, or slider library, record its name, exact version, purpose, upstream link, local asset path or embedding approach, initialization example, and readable fallback here. Keep required assets local or embedded, and test from a file: URL without network access.

Use inline styles for the palette and page presentation so a standalone uploaded HTML preview can still render. A preview may lack the repository paths needed to follow relative links. The complete repository is the reference for navigation testing.

Review before adding a page

  • Choose a layout that serves the content. A guide can use a sidebar, an architecture page can lead with a diagram, and a homepage can use cards.
  • Write the documentation in English. Preserve evidence, commands, and source links. Distinguish deployed behavior, observations, and planned work.
  • Check desktop and narrow layouts, keyboard focus, local links, and the behavior of interactive controls. Add the document to the homepage or its relevant parent route.
